# 004 · ต้นทุนรถยังอ่านได้ทาง REST ตรงที่ตารางฐาน (เหลือจาก v1.50)

สถานะ: เปิด · พบ 31 ส.ค. 2569 ตอนยิงพิสูจน์ migration 30

## อาการ

v1.50 ปิดทางอ่านของแอปแล้ว — โหมดจริงอ่านรถผ่านวิว `unit_v` ที่ตัด `cost/cost_vat`
เป็น null เมื่อไม่มีสิทธิ์ `data:money` (พิสูจน์แล้ว: sales1 เห็น 29 แถว cost null หมด)
แต่พนักงานที่รู้ publishable key + รหัสผ่านตัวเอง ยิง REST ตรงที่**ตารางฐาน**ได้:

    GET /rest/v1/motorcycle_unit?select=cost   → ตอบ cost จริง (ในขอบเขตสาขาตาม RLS)

RLS กรอง "แถว" ตามสาขาให้ แต่ไม่กรอง "คอลัมน์" — เส้นแบ่งคอลัมน์อยู่ที่วิวเท่านั้น
ซึ่งคุมได้เฉพาะทางที่แอปใช้ ไม่ใช่ทุกทางที่เข้าถึงตารางได้

## ทำไมยังไม่ปิดในรอบ v1.50

ทางปิดตรง ๆ คือ `revoke select (cost, cost_vat) on motorcycle_unit from authenticated`
แต่ upsert ของแอป (`dbUp` = INSERT … ON CONFLICT DO UPDATE ที่ PostgREST สร้าง)
อ้าง `excluded.cost` ซึ่ง**ต้องมี SELECT privilege บนคอลัมน์นั้น** — revoke แล้ว
`saveRecv`/แก้ราคา/ขายส่งย้ายสาขา พังทันทีสำหรับทุกบทบาท (สิทธิ์คอลัมน์แยกต่อผู้ใช้ไม่ได้
เพราะทุกคนคือ role `authenticated` เดียวกัน)

## ทางแก้ที่เสนอ (รอเจ้าของสั่ง)

ย้ายการเขียน `motorcycle_unit` ทุกจุด (รับรถ · แก้ราคา · เปลี่ยนสถานะ · ย้ายสาขา)
เข้า RPC `security definer` ที่ตรวจสิทธิ์เอง แล้วค่อย revoke สิทธิ์คอลัมน์เงิน
ออกจาก `authenticated` — วิว `unit_v` เป็นทางอ่านเดียว RPC เป็นทางเขียนเดียว
(แบบเดียวกับ `punch_clock`/`next_doc_no` ที่ทำแล้ว) · ประเมิน ~1 รอบเต็มเพราะ
จุดเขียนรถมี 10+ จุดและต้องพิสูจน์ทีละบทบาท

## ระหว่างนี้

- ความเสี่ยงจำกัดที่ "พนักงานที่ล็อกอินได้และตั้งใจยิง API เอง" เห็นทุนของสาขาตัวเอง —
  คนนอก (anon) โดนกันสนิททั้งวิวและตาราง
- ห้ามถอย: ทางอ่านของแอปต้องอยู่บน `unit_v` เท่านั้น (ด่าน liveload-r50 ข้อ [11] ล็อกไว้)
