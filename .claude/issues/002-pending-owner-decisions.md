# 002 · ของที่รอเจ้าของตัดสิน (จากบรีฟแก้ไขครั้งที่ 2)

เปิด 24 ส.ค. 2569 · ระบบออกแบบเผื่อไว้แล้ว — ได้คำตอบเมื่อไหร่แก้จุดเดียวจบ

## 1. ระดับซีรีส์เลขใบกำกับรันร่วม (คำถามข้อ 7 — เจ้าของตอบ "ยังไม่แน่ใจ")

ตอนนี้ใช้ default ปลอดภัย: **ซีรีส์เดียวต่อบริษัทต่อปี** ใช้ร่วมทั้ง 3 ส่วนของหน้าใบกำกับ
(ลูกค้า / ขายส่ง / อื่นๆ) — ใบเสร็จและใบส่งของขายส่งใช้เลขเดิมแยกตามสาขา

- ที่แก้เมื่อได้คำตอบ: `nextTaxNo()` / `taxKey()` / `taxPrefix()` ใน index.html (จุดเดียว)
- คำถามที่ต้องถาม: รันข้ามสาขาในบริษัทเดียวกันแบบตอนนี้ใช่ไหม หรือแยกต่อสาขา?
  ใบเสร็จรับเงินต้องเข้าซีรีส์เดียวกันด้วยหรือแยกแบบตอนนี้?
- รายงานภาษี (แท็บ tax) ยังโชว์เลขบิล/เลขที่การขายเดิม — ค่อยสลับเป็นเลขซีรีส์รวม
  หลังเจ้าของยืนยัน จะได้ไม่รื้อซ้ำ

## 2. เซลล์พิมพ์ใบเสร็จ (บรีฟข้อ 25)

คำสั่งเดิม v1.11 "ให้แต่บัญชีและผู้บริหาร" ยังไม่ถูกยกเลิก — ปุ่มพิมพ์ใบเสร็จบนแถบดีล (v1.36)
จึงโชว์เฉพาะคนที่มีสิทธิ์ act:printDoc · ถ้าเจ้าของอยากให้เซลล์พิมพ์ได้:
แก้ default ของ `act:printDoc` ใน PERM_ACTS (หรือแอดมินติ๊กเองที่หน้าปรับแต่ง ไม่ต้องแก้โค้ด)

## 3. เปลี่ยนตำแหน่งหลักของพนักงาน (v1.39)

หลายตำแหน่งทำได้แล้ว (union) แต่ "ตำแหน่งหลัก" (ป้าย/คู่มือ/แถบล่างมือถือ) ยังตายตัวตาม
`s.role` — ถ้าเจ้าของต้องการสลับหลัก ให้เพิ่มตัวเลือกในโมดัล `staffRolesModal`

## 4. เลขเอกสารเป็นสตริงซ้ำกันได้ระหว่างสาขาที่ใช้ prefix เดียวกัน (พบ 28 ส.ค. 2569 ตอนทำ v1.45)

`nextDocNo(branchCode, type)` นับตัวเลขแยกตาม**รหัสสาขา** แต่พิมพ์ออกมาด้วย `bOf(code).prefix`
ซึ่ง FMG01 · FMG02 · FMG03 ใช้ `FMG` เหมือนกันทั้งสามสาขา ⇒ บิลใบแรกของ FMG01 กับของ FMG02
ได้สตริงเดียวกันเป๊ะ: `FMG-WSALE-2569-00001`

- ผลกับงานจริง: เอกสารสองใบเลขเดียวกันในบริษัทเดียวกัน — ปัญหาแน่นอนถ้าใช้กับใบกำกับ/ใบเสร็จจริง
- ผลกับด่านตรวจ: จับคู่แถวด้วย `docNo` ไม่ได้ (ด่าน `wsvoid-r45` ตกหลุมนี้ตอนเขียน)
- ทางแก้ที่เป็นไปได้ (ต้องให้เจ้าของเลือก เพราะกระทบเลขที่ออกไปแล้ว):
  ① ใส่ `branchNo` ต่อท้าย prefix (`FMG00001-WSALE-…`) ② นับรวมทั้งบริษัทแทนรายสาขา
  ③ ตั้ง prefix ให้ไม่ซ้ำกันตั้งแต่หน้าตั้งค่าสาขา (แก้ข้อมูล ไม่ต้องแก้โค้ด)
- **ยังไม่แก้** เพราะอยู่นอกคำสั่งรอบ v1.45 และการเปลี่ยนรูปเลขเอกสารต้องให้เจ้าของยืนยันก่อน

## 5. `voidSaleCore` ฝั่งขายปลีกไม่มีด่านสิทธิ์ในฟังก์ชันเขียน (พบ 28 ส.ค. 2569)

`cancelSale(saleId)` เปิด modal แล้ว `#cvGo` เรียก `voidSaleCore(s)` ตรง ๆ — สิทธิ์ `canVoidSale()`
กันแค่ที่ **ปุ่ม** (`:7182`) ซึ่งขัดกฎ §9b ที่ทั้งโปรเจกต์ยึด (`custDropModal` ทำถูกอยู่แล้ว)
· ฝั่งขายส่ง (`wsVoid` v1.45) ทำถูกตั้งแต่ต้น **ห้ามลอกรูปแบบของ `cancelSale`**
· แก้ = ย้าย `if(!canVoidSale())` เข้าไปใน `voidSaleCore` + เพิ่มเคสในด่าน — งานเล็ก แต่ไม่อยู่ในคำสั่งรอบไหน
