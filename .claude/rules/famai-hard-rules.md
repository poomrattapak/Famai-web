# กฎถาวรของโปรเจกต์นี้ — ย่อจาก docs/04-design-system.md

กฎพวกนี้ได้มาจากของพังจริงหรือคำสั่งเจ้าของโดยตรง ละเมิดข้อไหน = ด่านตรวจแดงหรือเจ้าของตีกลับ
(รายละเอียดเต็ม + เหตุผล + ตัวอย่าง อยู่ใน `docs/04-design-system.md` ตาม § ที่อ้าง)

## โครงสร้าง UI

1. **กล่องได้ไม่เกิน 2 ชั้น** (§9c — คำสั่งเจ้าของคำต่อคำ) — ระหว่างขอบจอกับตัวหนังสือ
   มีสิ่งที่กินระยะด้านข้างได้ไม่เกิน 2 ชั้น (ปกติ `.card` + `.bd`) ข้างในแยกด้วย**เส้นคั่น**เท่านั้น
   ห้ามใส่พื้น มุมโค้ง หรือ margin ด้านข้างให้ลูกของ `.card`
2. **ห้ามเลื่อนซ้าย-ขวาที่ 390px** ทุกหน้า ทุกบทบาท (ยกเว้น `.doc` และ `.tw` ที่เป็นกับดักตั้งใจ)
3. **สถานะสื่อด้วยข้อความ+จุดสีเสมอ ห้ามสีอย่างเดียว** · ปุ่มที่กดแล้วไม่ทำงาน = ห้ามมี
   (รวมสถานะ "เลือกไว้แต่ยังไม่ได้ใช้" ด้วย — ต้องมีข้อความ ไม่ใช่แค่ปุ่มเปลี่ยนสี)
   - **token ที่พลิกตามธีม ห้ามใช้ข้ามบทบาท** — `--card` เป็นสีเข้มในธีมมืด ใช้เป็นสีตัวอักษร
     บนพื้น `--dark` แล้วตัวหนังสือหายทั้งแผง · พื้นที่ที่ต้องหน้าตาเหมือนกันทุกธีมให้ประกาศ
     token ของตัวเองที่ `:root` แล้วไม่ override ในธีมไหนเลย (เช่น `--login-fg`)
4. เส้นทางที่มีขั้นตอน = แถบขั้น (`steps()`) ไม่ใช่กระดานคัมบัง (§9f) · แถบคืบหน้าเป็นตัวบอกสถานะ ไม่ใช่ปุ่ม
5. งานหนึ่งชิ้นจบในหน้าเดียว ปุ่มไม่เด้งข้ามหน้า (§9g)
6. เงิน: `1,354,302 ฿` + tabular-nums · วันที่ พ.ศ. เสมอ · เลขเครื่อง/ถัง monospace ·
   คนไม่มีสิทธิ์ `money` เห็น `—` ไม่ใช่เลขจาง

## ตรรกะ

7. **ด่านอยู่ในฟังก์ชันที่เขียนข้อมูล ไม่ใช่ที่ปุ่ม** (§9b) — ซ่อนปุ่มไม่ใช่การกัน
   ทดสอบด้วยการเรียกฟังก์ชันเขียนตรง ๆ ด้วยบทบาทที่ต้องห้าม
8. **ขั้นตอน/สถานะคำนวณจากระเบียนจริง ห้ามเก็บเป็นฟิลด์ที่สาม** (§9g) — `dealOf()` คือต้นแบบ
   เก็บซ้ำเมื่อไหร่ต้องมี sync และ sync คือที่อยู่ของบั๊ก
9. **ผลการตัดสิน ณ เวลาทำรายการ ให้แช่ลงหลักฐาน** (§9i) — ห้ามคำนวณใหม่ตอนวาดจอ
   ไม่งั้นการแก้ config วันนี้จะพลิกประวัติที่ตรวจไปแล้ว
10. เวลาที่มีผลกับเงินมาจากเซิร์ฟเวอร์ (`punchNow()`) ไม่ใช่นาฬิกาเครื่องพนักงาน (§9i)
11. ยังไม่ได้ตั้งค่า = ปล่อยผ่านพร้อมติดธง ไม่ใช่บล็อกทั้งบริษัท (§9i — fail-open when unconfigured)
12. รวมหน้าที่สิทธิ์ไม่เท่ากัน → แท็บต้องเป็นด่านจริงใน handler ไม่ใช่แค่ซ่อนปุ่ม (§9h)

## ความเป็นส่วนตัว

13. เพื่อนร่วมงานไม่เห็นข้อมูลส่วนตัวของกัน (§9b v1.6): เงินเดือน เลขบัญชี รูป/พิกัดลงเวลา
    ประเภทการลา (เห็นแค่ "ลา · ชื่อเล่น") · เลขบัตรลูกค้าปิดกลางเสมอ ยกเว้นบทบาทที่ได้สิทธิ์
14. หน้าสาธารณะ: เคสไฟแนนซ์ไม่ผ่านขึ้นแค่ **"กรุณาติดต่อร้าน"** — ห้ามคำว่า "ไม่ผ่าน" ห้ามเหตุผล
    ห้ามชื่อเจ้าไฟแนนซ์ (ลูกค้าอาจเปิดลิงก์ต่อหน้าครอบครัว) · สต๊อกสาธารณะบอกแค่ มี/เหลือน้อย/หมด
    ไม่มีตัวเลข (ตัวเลขรายวัน = ยอดขายที่คู่แข่งอ่านได้)
