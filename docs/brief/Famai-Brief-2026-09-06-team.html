ข้อมูลลูกค้าและรายการดีล

ข้อ 01–03, 06, 12 · ทีมหน้าร้าน / ผู้บริหาร / ทีมพัฒนา

รุ่นรถ: เข้าใจง่ายที่หน้าร้าน

  • ตั้งค่ารหัสรุ่นยืดหยุ่น ไม่บังคับ 6 ตัว แนวทางใช้งาน: 1–40 ตัว รองรับตัวอักษรอังกฤษ ตัวเลข จุด ขีด และขีดล่าง พร้อมตัดช่องว่างและตรวจรหัสซ้ำ
  • เพิ่มลูกค้าให้เลือกเฉพาะชื่อรุ่น; ข้อมูลรหัสรุ่นยังเก็บภายในสำหรับขั้นตอนที่จำเป็น และการแก้ลูกค้าเดิมต้องไม่เปลี่ยนรหัสเดิมโดยไม่ตั้งใจ

ช่วงเวลาและการอัปเดต

  • ใช้ เวลาอัปเดตล่าสุดของลูกค้า/ดีล เป็นฐานกรองช่วงเวลาในหน้านี้ ระบุความหมายบนหน้าจอให้ชัด
  • แสดงรายการ ตัวเลขสรุป และจำนวนในแต่ละขั้นจากผลกรองเดียวกัน; ล้างตัวกรองได้ และแสดงผลว่างอย่างชัดเจน
  • เรียงใหม่ล่าสุดก่อน; เวลาเปลี่ยนเมื่อข้อมูลลูกค้า ไฟแนนซ์ ขาย จอง ส่งมอบ หรือบริการเปลี่ยน ใช้วัน พ.ศ. และเวลาไทย
  • เพิ่มลูกค้าสำเร็จต้องเปิดเห็นลูกค้าที่เพิ่งเพิ่ม แม้ตัวกรองก่อนหน้าไม่ตรง; ใช้สีร่วมกับข้อความ ไม่ใช้สีเพียงอย่างเดียว

คลังลูกค้าสำหรับนำไปใช้ต่อ

  • ปุ่มย้ายเข้าคลังแทนการลบทิ้ง ระบุเหตุผล ผู้ย้าย และเวลา; มีตัวกรอง “รายการดูแล / คลังลูกค้า” และปุ่มเรียกคืน
  • เก็บระเบียนลูกค้าเดิมพร้อมประวัติการซื้อ/บริการ/รุ่นที่สนใจ ไม่สร้างสำเนาลูกค้าซ้ำอีกฐาน
  • ห้ามย้ายเข้าคลังระหว่างมีจอง เคสไฟแนนซ์ที่ยังเดินงาน หรือขายที่ยังไม่ส่งมอบ; ต้องจัดการงานค้างให้จบก่อน
ตรวจรับ

เพิ่มลูกค้าแล้วพบในรายการทันที → แก้ข้อมูลแล้วขึ้นบนสุด → เลือกช่วงเวลาแล้วตัวเลขตรงตาราง → ย้ายเข้าคลังและเรียกคืนได้โดยประวัติครบ

ใบเสนอราคาและค่างวด

ข้อ 04–05, 07 · เซลล์ / ฝ่ายการเงิน

ใบเสนอราคาที่ตรวจสอบย้อนหลังได้

เงินสดเงินผ่อน
แสดงราคารถ ส่วนลด ค่าใช้จ่าย และยอดชำระเงินสดแสดงราคารถ ดาวน์ ยอดจัด บริษัทไฟแนนซ์ อัตรา จำนวนงวด และค่างวด
ออกเอกสารได้โดยไม่ต้องเลือกไฟแนนซ์รองรับเงื่อนไขและช่วงงวดของบริษัทที่เลือก
เก็บชื่อ/เบอร์เซลล์ ลูกค้า รุ่น และราคาของเอกสารเก็บเงื่อนไขทั้งชุด ณ วันออกเอกสาร
  • เลือกผู้ขายจริงได้ตามสิทธิ์; ชื่อและเบอร์โทรต้องติดไปทั้งตัวอย่าง ใบที่บันทึก และเอกสารพิมพ์
  • เมื่อแก้ราคาหรือเรตกลางภายหลัง ใบเสนอราคาเดิมต้องไม่เปลี่ยนตาม; เอกสารเก่าที่ไม่มีข้อมูลแช่ไว้ต้องสื่อข้อจำกัดชัด
  • ตรวจเส้นทางสร้าง → บันทึก → เปิดย้อนหลัง → พิมพ์ → ทำรายการขายต่อ ทั้งเงินสดและเงินผ่อน

เครื่องคำนวณค่างวดสำหรับเซลล์

01เลือกรุ่นใช้ข้อมูลรุ่นกลาง
02กรอกราคาและดาวน์คงราคาที่เซลล์กรอก
03เลือกไฟแนนซ์อ่านเรตตามบริษัท/ช่วงงวด
04ดูตารางเทียบจำนวนงวดและยอดต่อเดือน
  • ตารางต้องคำนวณใหม่เมื่อเปลี่ยนราคา ดาวน์ หรือบริษัท และตรวจดาวน์เกินราคา/ตัวเลขติดลบ
  • ข้อมูลไฟแนนซ์มาจากเรตที่บันทึกในระบบของแต่ละบริษัท การเชื่อม API ภายนอกยังไม่อยู่ในบรีฟ
  • ถ้าข้อมูลเรตยังไม่พร้อม ต้องให้ผู้ดูแลเติมข้อมูลจริงก่อนใช้กับลูกค้า ไม่อ้างตัวอย่างว่าเป็นข้อเสนอที่อนุมัติแล้ว
ตรวจรับ

ทดสอบเปลี่ยนบริษัทและช่วงงวด ตรวจยอดกับข้อมูลเรตที่ใส่ไว้ และเปิดใบเสนอราคาเก่าหลังเปลี่ยนเรตกลางเพื่อยืนยันว่าตัวเลขเดิมยังอยู่

โฟลวขายและด่านก่อนส่งมอบ

ข้อ 08–10, 13–14 · เซลล์ → ผู้บริหาร → การเงิน

เส้นทางเงินผ่อน

01เซลล์ยื่นไฟแนนซ์เลือกชื่อรุ่น รหัสรุ่น สี และเงื่อนไข; ยังไม่มีคันรถ
02ติดตามผลอยู่ในหน้าและขั้นไฟแนนซ์จนทราบผล
03ผู้บริหารเปิดขายหลังอนุมัติจึงเลือกคันตรงรุ่น/สีและจองสต๊อก
04ฝ่ายการเงินตรวจตรวจรับเงิน/เอกสารและบันทึกผล
05เซลล์ส่งมอบกดได้เมื่อผ่านทุกด่าน; เริ่มงานติดตาม 1 เดือน

เส้นทางเงินสด

ลูกค้า → ใบเสนอราคา → ผู้บริหารจัดคันและเปิดขาย → การเงินอนุมัติ → ส่งมอบ

ข้ามการยื่นสินเชื่อภายนอก แต่ยังต้องผ่านฝ่ายการเงินภายในก่อนส่งมอบ

กฎที่ต้องบังคับจริง

  • เซลล์เห็นเฉพาะลูกค้าของตน รวมรายการเกี่ยวข้องและคำขอข้อมูลโดยตรง; การมีบทบาทสต๊อกร่วมไม่เปิดลูกค้าของผู้อื่นให้เอง
  • การเลือกคันรถเป็นสิทธิ์จัดสรรของผู้บริหาร/ผู้จัดการในขั้นเปิดขาย; คันต้องว่าง ตรงรุ่น/สีและสาขา
  • มีปุ่มอนุมัติให้การเงินในดีลที่เปิดขายแล้ว; ผู้จัดคันไม่รับสิทธิ์อนุมัติการเงินโดยอัตโนมัติ
  • เงินสดและผ่อนห้ามส่งมอบก่อนการเงินผ่าน; ผ่อนต้องมีไฟแนนซ์ผ่านด้วย บังคับทั้ง handler และฐานข้อมูล
  • ถ้าเงื่อนไขหรือผลไฟแนนซ์เปลี่ยนก่อนส่งมอบ ต้องกลับให้การเงินตรวจใหม่; หลังส่งมอบรักษาหลักฐานผู้อนุมัติและเวลาจริง
ตรวจรับกรณีเสี่ยง

ทดลองเรียกคำสั่งส่งมอบตรงโดยเซลล์ / แก้สิทธิ์ระหว่างเปิดหน้าจอ / จัดคันเดียวกันซ้ำ / ฐานข้อมูลปฏิเสธ / กดยืนยันซ้ำ ต้องไม่เกิดการขายหรือส่งมอบผิดสถานะ

แจ้งเตือนและการส่งต่องาน

ข้อ 11 และส่วนเชื่อมข้อ 03, 06, 16

ประสบการณ์แบบกระดิ่งงาน

  • แสดงจำนวนที่ยังไม่อ่าน แยกหมวดงานตามสิทธิ์และขอบเขตสาขา; งานใหม่มีข้อความแจ้งในแอป
  • รายการยังไม่อ่านเด่นกว่า อ่านแล้วจางลงพร้อมข้อความ “อ่านแล้ว” และเก็บสถานะอ่านแยกผู้ใช้
  • กดแล้วเข้าหน้าที่ถูกต้องและเปิดดีล ลูกค้า ใบงาน หรือนัดหมายนั้นโดยตรง รวมรายการที่อยู่หน้าถัดไป
  • งานที่ทำเสร็จไม่ค้างในคิวเตือน; การอ่านแจ้งเตือนยังไม่ถือว่าทำงานสำเร็จ
เหตุการณ์ผู้รับงานปลายทาง
เปิดขายแล้ว รอการเงินฝ่ายการเงินตามสิทธิ์ดีลของลูกค้า → ตรวจและอนุมัติ
ไฟแนนซ์ผ่าน ยังไม่เปิดขายผู้บริหาร/ผู้จัดการดีลของลูกค้า → จัดคันและเปิดขาย
การเงินผ่าน พร้อมส่งมอบเซลล์เจ้าของ / ผู้บริหารดีลของลูกค้า → ส่งมอบ
นัดบริการใกล้ครบ/เลยกำหนดฝ่ายบริการหลังการขาย → งานนัดของลูกค้า
งานอื่นในระบบเดิมฝ่ายที่รับผิดชอบหน้าและระเบียนของงานนั้น

การโหลดข้อมูลข้ามเครื่อง

  • อัปเดตงานระหว่างเปิดใช้งานเป็นระยะ และตอนกลับเข้าแอป; ไม่เขียนทับฟอร์มที่กำลังกรอก
  • ดึงรายการตามสิทธิ์จากฐาน ไม่ใช้เพียงการซ่อนด้วย CSS; ตรวจ read state หลังโหลดใหม่
  • ขอบเขตบรีฟคือแจ้งเตือนในเว็บที่เปิดอยู่ ไม่รวมอีเมล LINE หรือ push ตอนปิดเว็บ
ตรวจรับ

สร้างงานจากบทบาทหนึ่ง → อีกฝ่ายเห็นงาน → กดกระดิ่งถึงรายการนั้น → เปิดซ้ำแสดงอ่านแล้ว → ทำงานเสร็จแล้วหายจากคิวที่ต้องทำ

บริการหลังการขายรูปแบบใหม่

ข้อ 15–16 · ฝ่ายบริการ

รับลูกค้าทั้งจากร้านและรถนอก

01ค้นรถก่อนกรอกเลขเครื่องหรือเลขถังเต็มเลข
02พบประวัติใช้ลูกค้าและรถเดิม
03ไม่พบประวัติเพิ่มชื่อ เบอร์โทร รุ่นรถที่พิมพ์เองได้
04บันทึกบริการรายละเอียด + จำนวนเงินไม่บังคับ
05นัดรอบถัดไปปุ่มสีแดงเปิดวัน/เวลา; สร้างงานใหม่เมื่อยืนยัน
ประเภทงานจุดเริ่มต้นกติกา
อัตโนมัติหลังส่งมอบวันส่งมอบรถสำเร็จหนึ่งงาน “ติดตาม 1 เดือนหลังส่งมอบ”; บวกเดือนปฏิทินและปรับวันปลายเดือน
บริการที่พนักงานเพิ่มลูกค้าเข้ารับบริการบันทึกรายละเอียดและราคา (เว้นว่างได้) เป็นประวัติ; เพิ่มนัดต่อได้
นัดบริการครั้งถัดไปวัน/เวลาที่เลือกงานใหม่เชื่อมบริการเดิม มี checkbox ให้ปิดเมื่อเข้ารับบริการ
  • เลิกสร้างชุด task เดิม; เก็บหลักฐานเก่าเป็นประวัติ ไม่ให้ปะปนคิวงานใหม่
  • งานอัตโนมัติไม่รอรับป้ายทะเบียน; เตือนสีแดงตั้งแต่ก่อนครบ 7 วันและคงเตือนเมื่อเลยกำหนด
  • งานอัตโนมัติและนัดเองมี checkbox พร้อมเวลา/ผู้ปิดงาน และแยกตามรถเมื่อคนเดียวมีหลายคัน
  • จำนวนเงินว่างต้องแยกจากกรอก 0; นัดใช้เวลาไทย; กดซ้ำต้องไม่สร้างงานซ้ำ
  • บันทึกลูกค้า บริการ และนัดให้เชื่อมครบ; ฐานปฏิเสธต้องแจ้งและยังแก้/ลองใหม่ได้
ตรวจรับวันขอบเขต

ส่งมอบ 31 มกราคม → ติดตามวันสุดท้ายของกุมภาพันธ์; ก่อนครบ 8 วันไม่เตือน ก่อนครบ 7 วันเริ่มเตือน; ลูกค้ารับบริการและติ๊กเสร็จแล้วหยุดเตือน

ออกแบบสิทธิ์ให้เลือกได้ง่าย

  • แบ่งหมวดตามงาน: หน้าจอ / การกระทำสำคัญ / ข้อมูลที่เห็น เลือกบทบาทและค้นหารายการสิทธิ์ได้
  • มีแม่แบบเริ่มต้นตามตำแหน่ง เช่น เซลล์ การเงิน ฝ่ายบริการ ผู้จัดการ แล้วปรับรายละเอียดก่อนบันทึก
  • หน้าจอแยก “ไม่มีสิทธิ์ / ดูอย่างเดียว / เพิ่มและแก้ไข” ส่วนการอนุมัติ ส่งมอบ จัดคัน และย้ายเข้าคลังเป็นสิทธิ์การกระทำ
  • อ่านอย่างเดียวต้องเขียนไม่ได้แม้กดเรียกฟังก์ชันตรง; การให้สิทธิ์การกระทำต้องไม่ข้ามสิทธิ์หน้าต้นทาง
บทบาทงานหลักข้อจำกัดสำคัญ
เซลล์ลูกค้าตนเอง ใบเสนอราคา ยื่นไฟแนนซ์ ส่งมอบหลังผ่านไม่จัดคัน ไม่อนุมัติเงิน ไม่เห็นลูกค้าเซลล์อื่น
ผู้บริหาร/ผู้จัดการภาพรวมและจัดคันตอนเปิดขายสิทธิ์จัดคันแยกจากอนุมัติการเงิน
ฝ่ายการเงินตรวจเงิน/เอกสารและอนุมัติก่อนส่งมอบต้องมีสิทธิ์แก้ดีลและอนุมัติ
ฝ่ายบริการลูกค้าบริการ บันทึกงาน นัดหมาย และติดตามไม่ให้สิทธิ์อนุมัติขายเพิ่มโดยอัตโนมัติ
ผู้ดูแลระบบกำหนดแม่แบบและสิทธิ์ตรวจสิทธิ์จริงในฐานให้ตรงหน้าจอ

หลักฐานและการนำขึ้นใช้งาน

  • ใช้เวลาเซิร์ฟเวอร์กับการอนุมัติ อัปเดต และปิดงาน พร้อมผู้ดำเนินการ; ราคา/เรตบนเอกสารเป็นข้อมูล ณ เวลาบันทึก
  • ปรับโครงสร้างฐานและหน้าเว็บเป็นรุ่นที่ใช้ร่วมกันได้; ทดสอบย้ายข้อมูลเก่าและการอ่านด้วยบทบาทจริงก่อนเผยแพร่
  • ไม่ลบประวัติธุรกรรมเดิม; ลูกค้าไม่มีเจ้าของชัดให้ผู้บริหารจัดสรร ไม่สุ่มให้เซลล์
  • ตรวจหน้าจอคอม 1440px / มือถือ 390px ทั้งสว่างและมืด รวมข้อความผิดพลาดและสถานะกำลังบันทึก

ข้อหัวข้องานเกณฑ์ผ่าน
01รหัสรุ่นยืดหยุ่นบันทึกรหัสสั้น/ยาวกว่า 6 ตัว และแจ้งเมื่อซ้ำหรือรูปแบบไม่ถูกต้อง
02เลือกชื่อรุ่นได้ง่ายรายการแสดงชื่อรุ่น ไม่มีรหัสต่อท้าย; รุ่นชื่อซ้ำไม่ทำให้เลือกสับสน
03ตัวกรองช่วงเวลาและสีตาราง จำนวนรวม และภาพรวมขั้นตอนใช้ชุดข้อมูลเดียวกัน
04ชื่อและเบอร์เซลล์เอกสารแสดงผู้ขายจริงและเก็บข้อมูล ณ วันออกเอกสาร
05ใบเสนอราคาเงินสด/ผ่อนบันทึก เปิดดู และพิมพ์ได้ทั้งสองวิธีชำระ
06เรียงตามอัปเดตล่าสุดรายการที่แก้ล่าสุดขึ้นก่อน พร้อมวันและเวลาไทย
07เครื่องคำนวณของเซลล์เลือกรุ่น ราคา ดาวน์ บริษัท แล้วเห็นตารางงวดตามเรตบริษัท
08ลูกค้าของเซลล์แต่ละคนเซลล์อ่านและแก้ข้อมูลของเซลล์อื่นไม่ได้ รวมการเรียกฐานโดยตรง
09ปุ่มอนุมัติของการเงินฝ่ายการเงินเห็นงานรอตรวจและบันทึกผลได้
10ห้ามส่งมอบก่อนอนุมัติเงินสดและผ่อนถูกบล็อกทั้งหน้าจอและฐานข้อมูล
11กระดิ่งแจ้งเตือนตรงงานเห็นงานตามสิทธิ์ อ่านแล้วจางลง กดแล้วเปิดรายการที่เกี่ยวข้อง
12ย้ายลูกค้าเข้าคลังซ่อนจากงานประจำได้โดยข้อมูล/ประวัติไม่หาย และกู้คืนได้
13ยื่นไฟแนนซ์ด้วยรุ่น/สีไม่มีการเลือกคัน; ผู้บริหารจัดคันเมื่อเปิดขาย
14แก้เส้นทางยื่นไฟแนนซ์ยื่นสำเร็จอยู่ในขั้นไฟแนนซ์ ไม่กระโดดไปเปิดขาย
15รับบริการรถนอกร้านค้นเลขเครื่อง/ถังก่อน; ไม่พบจึงเพิ่มลูกค้าและพิมพ์รุ่นเอง
16งานบริการรูปแบบใหม่หนึ่งงานหลังส่งมอบ 1 เดือน + งานเอง/นัดถัดไป; เตือนก่อน 7 วัน
17แม่แบบและหมวดสิทธิ์เลือกบทบาท/แม่แบบง่าย แบ่งหมวดหน้าจอ การกระทำ และข้อมูล
18สิทธิ์ดูและแก้ไขแยกไม่ให้เข้าถึง/ดูอย่างเดียว/เพิ่มและแก้ไข และบังคับตอนเขียนจริง
19เชื่อมทุกส่วนและอุดช่องว่างตรวจเงินสด/ผ่อน งานร่วมหลายฝ่าย ข้อมูลหลังโหลดใหม่ และมือถือ

ข้อมูลผู้รับผิดชอบใช้ตรงไหน
เรต/ช่วงงวด/เงื่อนไขไฟแนนซ์ล่าสุดการเงิน / ผู้ดูแลเครื่องคำนวณและใบเสนอราคา
ชื่อและเบอร์โทรเซลล์ผู้ดูแลพนักงานใบเสนอราคาและการตรวจสอบย้อนหลัง
รายชื่อผู้จัดคันและผู้อนุมัติเงินผู้บริหารตั้งแม่แบบและสิทธิ์จริง
เจ้าของลูกค้าเดิมที่ยังว่างผู้บริหาร / หัวหน้าเซลล์แยกการมองเห็นโดยไม่ทำข้อมูลหาย

ข้อเสนอแนะเพิ่มเติมจากภาพรวม

  • การตลาด: เพิ่มสถานะอนุญาตติดต่อ ช่องทางที่สะดวก และวันติดต่อครั้งล่าสุดก่อนส่งออกไปทำแคมเปญ; การย้ายเข้าคลังไม่เท่ากับยินยอมรับการตลาด
  • เจ้าของลูกค้า: มีขั้นตอนโอนผู้รับผิดชอบเมื่อลาออก/ย้ายสาขา พร้อมประวัติว่าใครโอนให้ใคร
  • นัดหมาย: เพิ่มเหตุผลเลื่อนนัด ไม่มาตามนัด หรือปฏิเสธการติดต่อ เพื่อให้คิวบริการตรงงานจริง
  • การเงิน: ระบุวันเริ่มใช้และวันหมดอายุของเรตแต่ละชุด พร้อมผู้ยืนยัน จะช่วยลดการใช้เรตเก่า
  • การติดตามระบบ: แยกผล “บันทึกแล้ว” กับ “รอส่งข้อมูล” ให้เห็นได้ และมีวิธีตรวจรายการที่ส่งไม่สำเร็จ
