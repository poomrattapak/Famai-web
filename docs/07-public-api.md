# API สาธารณะสำหรับเว็บขายรถ

คู่มือนี้เขียนให้ **คนทำเว็บขายรถ** อ่านคนเดียวจบ ไม่ต้องเปิดโค้ดของระบบหลังบ้าน

---

## 1. ภาพรวม

เว็บขายรถดึงข้อมูลจากฐานข้อมูลเดียวกับที่ร้านใช้ทำงาน ผ่าน **Supabase REST**
ไม่มีเซิร์ฟเวอร์ตัวกลาง ไม่ต้องติดตั้งอะไร ใช้ `fetch` ธรรมดาก็เรียกได้

| ดึงอะไรได้ | เรียกยังไง |
|---|---|
| แคตตาล็อกรุ่นรถ + ราคา + สี + รูป + สถานะของ | `GET /rest/v1/model` |
| สถานะการซื้อของลูกค้าคนหนึ่ง (ต้องมีรหัส) | `POST /rest/v1/rpc/order_status` |
| รูปรถ | เรียก URL ของ Storage ตรง ๆ ผ่าน CDN |

### กฎเดียวที่ต้องจำ

ฐานข้อมูลมีสองสคีมา

- **`pub`** — สาธารณะทั้งหมด ทุกอย่างในนี้ตั้งใจให้คนนอกเห็น
- **`public`** — ข้อมูลจริงของร้าน **คนนอกแตะไม่ได้เลย** ถูกถอนสิทธิ์ออกหมดแล้ว

เว็บขายรถเรียกได้เฉพาะของในสคีมา `pub` ถ้าเรียกอย่างอื่นจะได้ error ไม่ใช่ข้อมูล

## 2. เริ่มใน 5 นาที

คัดลอกไฟล์นี้ไปวางเป็น `index.html` แล้วเปิดด้วยเบราว์เซอร์ได้เลย ไม่ต้องใช้เฟรมเวิร์ก

```html
<!doctype html>
<meta charset="utf-8">
<title>รถของเรา</title>
<style>
  body{font-family:system-ui,sans-serif;margin:24px;background:#faf9f7}
  .grid{display:grid;gap:16px;grid-template-columns:repeat(auto-fill,minmax(220px,1fr))}
  .card{background:#fff;border-radius:16px;padding:16px;box-shadow:0 1px 3px #0001}
  .card img{width:100%;aspect-ratio:1;object-fit:cover;border-radius:12px}
  .price{font-size:20px;font-weight:700}
  .tag{font-size:12px;padding:2px 10px;border-radius:999px}
  .ready{background:#E7F6EE;color:#1F7A4D}
  .low{background:#FDF3E7;color:#A96410}
  .order{background:#F1F1F3;color:#6B6C7E}
</style>
<div class="grid" id="g">กำลังโหลด…</div>
<script>
const URL = 'https://<โปรเจกต์>.supabase.co';
const KEY = '<publishable key>';
const LABEL = { ready:'มีรถพร้อมส่ง', low:'เหลือน้อย', order:'สั่งจอง' };

/* 'Accept-Profile': 'pub' ขาดไม่ได้ — ไม่ใส่จะได้ 404 เพราะสคีมาปริยายคือ public */
fetch(URL + '/rest/v1/model?select=*&order=retail.asc',
      { headers:{ apikey: KEY, 'Accept-Profile': 'pub' } })
  .then(r => r.json())
  .then(ms => {
    document.getElementById('g').innerHTML = ms.map(m => `
      <div class="card">
        ${m.photo ? `<img src="${m.photo}" alt="${m.model}" loading="lazy">` : ''}
        <h3>${m.model} <small>${m.model_th || ''}</small></h3>
        <div class="price">${m.retail ? m.retail.toLocaleString() + ' ฿' : 'สอบถามราคา'}</div>
        <div>${(m.colors || []).map(c => c.name).join(' · ')}</div>
        <span class="tag ${m.availability}">${LABEL[m.availability]}</span>
      </div>`).join('');
  });
</script>
```

ขอ `URL` กับ `KEY` จากเจ้าของร้าน — คีย์ตัวนี้ **เปิดเผยได้ตามการออกแบบ** วางไว้ในหน้าเว็บได้เลย
ความปลอดภัยมาจากสิทธิ์ที่ฐานข้อมูล ไม่ได้มาจากการซ่อนคีย์

## 3. Endpoint ทีละตัว

### 3.1 แคตตาล็อกรุ่นรถ

```
GET /rest/v1/model
    apikey:         <publishable key>
    Accept-Profile: pub          ← ขาดไม่ได้
```

> **`Accept-Profile: pub` ต้องมีทุกคำขอ** ไม่ใส่จะได้
> `404 · Could not find the table 'public.model'` เพราะสคีมาปริยายคือ `public`
> ซึ่งเป็นสคีมาที่คนนอกแตะไม่ได้ (สำหรับ `POST /rpc/…` ใช้ `Content-Profile: pub` แทน)

รองรับไวยากรณ์ของ PostgREST ทั้งหมด (กรอง เรียง แบ่งหน้า)

```bash
P=(-H "apikey: $KEY" -H "Accept-Profile: pub")

# ทุกรุ่น เรียงตามราคา
curl "$URL/rest/v1/model?select=*&order=retail.asc" "${P[@]}"

# เฉพาะที่มีของพร้อมส่ง
curl "$URL/rest/v1/model?availability=eq.ready" "${P[@]}"

# เฉพาะออโตเมติก ราคาไม่เกิน 60,000
curl "$URL/rest/v1/model?cat=eq.Automatic&retail=lte.60000" "${P[@]}"

# รุ่นเดียว
curl "$URL/rest/v1/model?code=eq.B6FU00" "${P[@]}"
```

คำตอบ:

```json
[
  {
    "code": "B6FU00",
    "model": "FINN",
    "model_th": "ฟินน์ ล้อแม็ก",
    "cat": "Moped",
    "cc": 114.00,
    "year": 2567,
    "retail": 46900.00,
    "photo": "https://<โปรเจกต์>.supabase.co/storage/v1/object/public/model-photo/model/B6FU00/card-a1b2c3.webp",
    "colors": [
      { "code": "010C", "name": "ฟ้า" },
      { "code": "0500", "name": "แดง" }
    ],
    "photos": [
      { "card": "…/card-a1b2c3.webp", "full": "…/full-d4e5f6.webp" }
    ],
    "availability": "ready"
  }
]
```

### 3.2 สถานะการซื้อของลูกค้า

```
POST /rest/v1/rpc/order_status
     apikey:          <publishable key>
     Content-Profile: pub          ← ขาดไม่ได้ (ฝั่ง POST ใช้ตัวนี้ ไม่ใช่ Accept-Profile)
     Content-Type:    application/json
     { "p_token": "A7K2-9MTX-4RBQ" }
```

```bash
curl -X POST "$URL/rest/v1/rpc/order_status" \
  -H "apikey: $KEY" -H "Content-Profile: pub" -H "Content-Type: application/json" \
  -d '{"p_token":"A7K2-9MTX-4RBQ"}'
```

เจอ:

```json
{
  "found": true,
  "status": "กำลังดำเนินการเรื่องทะเบียน",
  "model": "NMAX", "model_th": "เอ็นแม็กซ์", "color": "แดง",
  "plate": null,
  "due_at": "2026-09-08",
  "delivered_at": null,
  "customer": { "name": "สมชาย", "phone": "xxx-xxx-5678" },
  "shop": { "name": "Famai Motor Group", "phone": "02-000-0000" }
}
```

> **ตอนนี้ `shop.phone` ยังเป็น `null` ทุกสาขา** เพราะ `branch.phone` ในฐานข้อมูลยังว่าง
> หน้าติดตามบอกลูกค้าว่า "กรุณาติดต่อร้าน" แต่ยังไม่มีเบอร์ให้โทร — ต้องเติมก่อนเปิดใช้จริง
> ระหว่างนี้ให้เว็บ fallback ไปที่เบอร์กลางของร้านเมื่อค่าเป็น `null`

ไม่เจอ (รหัสผิด · การขายถูกยกเลิก · รหัสหมดอายุ) — **คำตอบเหมือนกันทั้งสามกรณี** โดยตั้งใจ

```json
{ "found": false }
```

### 3.3 รูปรถ

`photo` กับ `photos[].card/full` เป็น URL เต็มอยู่แล้ว เอาไปใส่ `<img src>` ได้ตรง ๆ
เสิร์ฟผ่าน CDN และตั้งแคชไว้ 1 ปี

| ชั้น | ขนาด | ใช้ที่ไหน | ขนาดไฟล์โดยประมาณ |
|---|---|---|---|
| `card` | 640×640 | กริดรายการรถ | 50–70 KB |
| `full` | 1600×1600 | หน้ารายละเอียดรถ | 250–400 KB |

รูปเป็น **WebP** (บางเครื่องที่อัปโหลดเป็น JPEG) และเป็นจัตุรัสเสมอ ครอปจากตรงกลาง

## 4. ฟิลด์ทั้งหมด

### `model`

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `code` | text | รหัสรุ่น 6 ตัว เช่น `B6FU00` |
| `model` | text | ชื่อรุ่นภาษาอังกฤษ |
| `model_th` | text | ชื่อรุ่นภาษาไทย (อาจเป็นค่าว่าง) |
| `cat` | text | ประเภท: `Automatic` · `Moped` · `Sport` |
| `cc` | number | ความจุกระบอกสูบ — JSON ส่งมาเป็น `114.00` (numeric ของฐานข้อมูล) JavaScript อ่านได้เป็น `114` ตามปกติ |
| `year` | int | ปีรุ่น (พ.ศ.) |
| `retail` | number | ราคาขายปลีก บาท (ส่งมาเป็น `46900.00`) — `null` = ยังไม่กำหนดราคา ให้แสดงว่า "สอบถามราคา" |
| `photo` | text | URL รูปปกชั้น card — `null` = ยังไม่มีรูป |
| `colors` | array | `[{code, name}]` เรียงตามรหัสสี |
| `photos` | array | `[{card, full}]` สูงสุด 4 มุม เรียงตามลำดับที่ร้านตั้งไว้ |
| `availability` | text | `ready` มีพร้อมส่ง · `low` เหลือน้อย · `order` ต้องสั่งจอง |

### `order_status`

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `found` | bool | `false` = รหัสใช้ไม่ได้ ไม่ต้องอ่านฟิลด์อื่น |
| `status` | text | ข้อความสถานะ 4 แบบ (ดู §5) |
| `model` · `model_th` · `color` | text | รถที่ซื้อ |
| `plate` | text | เลขทะเบียน — `null` = ยังไม่ออก |
| `due_at` | date | กำหนดที่ทะเบียนควรออก — `null` เมื่อส่งมอบแล้ว |
| `delivered_at` | date | วันที่รับรถ — `null` = ยังไม่ได้รับ |
| `customer.name` | text | ชื่อต้นของลูกค้าเท่านั้น |
| `customer.phone` | text | ปิดบังเหลือ 4 ตัวท้าย `xxx-xxx-1234` |
| `shop.name` · `shop.phone` | text | สาขาที่ซื้อ ไว้ให้ลูกค้าโทรถาม |

## 5. สิ่งที่ API ไม่ให้ และเหตุผล

ออกแบบเสมือนว่าทุกคำตอบคือข่าวประชาสัมพันธ์ — ถ้าไม่อยากให้ลงหนังสือพิมพ์ ก็ไม่ควรอยู่ใน API

| ไม่ให้ | เหตุผล |
|---|---|
| ต้นทุน · กำไร · ส่วนลด | กำไรของร้าน ไม่ได้อยู่ในวิวตั้งแต่แรก |
| เลขเครื่อง · เลขถัง · เลข PO · เลขใบรับ | เอกสารภายในและระบุตัวรถได้ |
| **จำนวนคงเหลือเป็นตัวเลข** | ดูข้อถัดไป |
| **รายการรถรายคัน** | ดูข้อถัดไป |
| รหัสสาขา · จำนวนแยกสาขา | ดูข้อถัดไป |
| ชื่อเต็ม · เบอร์เต็ม · ที่อยู่ · เลขผู้เสียภาษีของลูกค้า | ข้อมูลส่วนบุคคล |
| เหตุผลที่ไฟแนนซ์ไม่ผ่าน · ชื่อบริษัทไฟแนนซ์ | ดูข้อ §5.2 |
| ค่าคอมมิชชั่น · เรตไฟแนนซ์ · ดาวน์ขั้นต่ำ | เงื่อนไขทางการค้า |

### 5.1 ทำไมไม่บอกจำนวนคันและไม่มีรายการรายคัน

ถ้าบอกจำนวนจริง คนที่ดึงข้อมูลทุกวันจะรู้ยอดขายของร้านทันที
NMAX 2 คันวันนี้ เหลือ 1 คันพรุ่งนี้ = ขายไป 1 คัน เก็บไปหนึ่งเดือนก็รู้ยอดรายรุ่น
อัตราการขาย และอายุสต๊อกทั้งร้าน **API จะกลายเป็นเครื่องวัดยอดขายให้คู่แข่งฟรี ๆ**

รายการรายคันยิ่งแม่นกว่า เพราะนับแถวก็ได้จำนวนแล้ว จึงไม่มี endpoint ไหนคืนรายคันเลย
`availability` สามค่าบอกลูกค้าได้ครบว่าต้องรีบตัดสินใจไหม โดยไม่บอกตัวเลขให้ใคร

### 5.2 กฎเรื่องศักดิ์ศรีของหน้าติดตาม

`status` มีได้แค่ 4 แบบเท่านั้น

| ค่า | เมื่อไหร่ |
|---|---|
| `รับเรื่องแล้ว` | รับใบจองแล้ว |
| `กำลังดำเนินการเรื่องสินเชื่อ` | เคสไฟแนนซ์ยังไม่อนุมัติ |
| `กำลังดำเนินการเรื่องทะเบียน` | ผ่านไฟแนนซ์แล้ว รอทะเบียน |
| `ส่งมอบรถแล้ว · รอทะเบียนจากขนส่ง` | ลูกค้ารับรถแล้ว ใช้ป้ายชั่วคราว |
| `ส่งมอบรถแล้ว · ได้ทะเบียนเรียบร้อย` | จบครบทุกขั้น |
| `กรุณาติดต่อร้าน` | **ทุกกรณีที่ต้องคุยกัน รวมถึงไฟแนนซ์ไม่ผ่าน** |

**ห้ามแสดงคำว่า "ไม่ผ่าน" ห้ามบอกเหตุผล ห้ามบอกชื่อบริษัทไฟแนนซ์บนหน้าเว็บเด็ดขาด**
ลูกค้าอาจเปิดลิงก์นี้ต่อหน้าครอบครัวหรือที่ทำงาน
API ไม่ส่งข้อมูลพวกนี้ออกมาอยู่แล้ว และหน้าเว็บก็ต้องไม่เดาเองจากฟิลด์อื่น

## 6. รูปรถ — ขนาดและการประหยัดพื้นที่

รูปถูกย่อที่เครื่องของคนอัปโหลด **ก่อน** ขึ้นเซิร์ฟเวอร์ รูปดิบจากมือถือ 3–12 MB
จะไม่ถูกอัปเลย ระบบแปลงเป็น WebP สองชั้นแล้วอัปเฉพาะผลลัพธ์

ตัวอย่างที่วัดจริง: ต้นฉบับ 966 KB → `card` 66 KB + `full` 138 KB

ผลพลอยได้: การเข้ารหัสใหม่ **ลบ EXIF ทิ้ง** พิกัด GPS ที่ติดมากับรูปถ่ายจากมือถือ
จึงไม่หลุดออกไปกับเว็บสาธารณะ

## 7. แคช ลิมิต และการตั้งค่า

| เรื่อง | รายละเอียด |
|---|---|
| แคชแคตตาล็อก | ควรทำที่ฝั่งเว็บขาย (ISR/build-time) แคตตาล็อกเปลี่ยนไม่บ่อย — เรียกทุกครั้งที่มีคนเข้าเว็บสิ้นเปลืองเปล่า |
| แคชรูป | ตั้งไว้ 1 ปีแล้ว ชื่อไฟล์ผูกกับเนื้อไฟล์ เปลี่ยนรูปแล้วชื่อเปลี่ยน ไม่มีรูปเก่าค้าง |
| ลิมิตหน้าติดตาม | **20 ครั้ง/ชั่วโมง/ไอพี** เกินแล้วจะได้ error |
| CORS | Supabase เปิดให้อยู่แล้ว เรียกจากเบราว์เซอร์ได้เลย |

**การตั้งค่าฝั่ง Supabase ทำครบแล้วเมื่อ 9 ส.ค. 2569** — คนทำเว็บไม่ต้องแตะอะไร

| รายการ | สถานะ |
|---|---|
| migration 10–15 | รันครบแล้ว |
| สคีมา `pub` เปิดให้ PostgREST เห็น | เปิดแล้ว (ตั้งที่ role `authenticator` ท้าย migration 15 ไม่ใช่ที่หน้า Settings) |
| bucket `model-photo` | มีแล้ว เป็น public อ่านได้โดยไม่ล็อกอิน เขียนไม่ได้ |
| ถอนสิทธิ์ `anon` จากสคีมา `public` | ถอนแล้ว ตารางจริงทุกตัวตอบ 401 |

ถ้าวันหลังไปแก้ **Settings → API → Exposed schemas** ในหน้าเว็บแล้วไม่มีผล
ให้ดู `alter role authenticator set pgrst.db_schemas` ท้าย migration 15 — ค่าที่ตั้งกับ role ชนะค่าในหน้าเว็บ

## 8. รหัสติดตามของลูกค้า

- **12 ตัวอักษร** รูปแบบ `XXXX-XXXX-XXXX` เช่น `A7K2-9MTX-4RBQ`
- ตัดตัว **I L O U** ออกจากชุดอักษร เพราะลูกค้าต้องอ่านทางโทรศัพท์ได้โดยไม่สับสน
- 60 บิต — สุ่มเดาไม่เจอ และไม่มี endpoint ไหนที่ list รายการออกมาได้
- พิมพ์อยู่ **ท้ายใบเสร็จ** ของลูกค้าทุกใบ
- พิมพ์ตัวเล็กก็ค้นเจอ ระบบแปลงเป็นตัวใหญ่ให้เอง

| สถานการณ์ | ทำยังไง |
|---|---|
| ลูกค้าทำรหัสหาย | โทรมาที่ร้าน พนักงานเปิดหน้าดีลแล้วคัดลอกลิงก์ส่งให้ใหม่ |
| ลูกค้าส่งลิงก์ต่อผิดคน | ผู้บริหารกด "ออกรหัสใหม่" ที่หน้าดีล รหัสเดิมใช้ไม่ได้ทันที |
| การขายถูกยกเลิก | รหัสใช้ไม่ได้ทันทีโดยอัตโนมัติ |

**จะไม่มีทางเลือก "ค้นด้วยเบอร์โทร + ชื่อ" เด็ดขาด** เพราะนั่นคือเครื่องมือไล่เดาข้อมูลลูกค้าทั้งฐาน

### ข้อมูลส่วนบุคคล (PDPA)

- ฐานทางกฎหมายคือ **การปฏิบัติตามสัญญา** (ม.24(3)) ไม่ใช่ความยินยอม — โทเคนเป็นกุญแจถือครอง
- หน้าติดตามแสดงเฉพาะสิ่งที่ลูกค้ามีอยู่ในมือบนใบเสร็จของตัวเองอยู่แล้ว ไม่เพิ่มการเปิดเผยใหม่
- บันทึกการเรียกเก็บ **แฮชของไอพี ไม่เก็บไอพีจริง**
- โทเคนหมดอายุ 90 วันหลังส่งมอบ และเพิกถอนได้ทันทีถ้าลูกค้าขอ

## 9. แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| `PGRST106 Invalid schema: pub` | สคีมา `pub` หลุดจาก Exposed schemas — ดู §7 |
| `PGRST205 Could not find the table` ทั้งที่ตั้งค่าถูก | แคชสคีมาของ PostgREST ยังไม่รีเฟรช สั่ง `notify pgrst, 'reload schema';` แล้วรอ ~5 วินาที |
| ได้ `[]` เปล่า | เชื่อมได้แล้วแต่ไม่มีข้อมูล — ไม่ใช่ปัญหาสิทธิ์ |
| `permission denied for schema public` | เรียกตารางในสคีมา `public` — เรียกได้เฉพาะของใน `pub` |
| `JWT expired` / `Invalid API key` | ใช้คีย์ผิดตัว ต้องใช้ **publishable key** ไม่ใช่ service key |
| รูปไม่ขึ้น | ร้านยังไม่ได้อัปรูปรุ่นนั้น — `photo` เป็น `null` ให้เว็บวาด placeholder เอง |
| `ขอข้อมูลถี่เกินไป` | ชนลิมิต 20 ครั้ง/ชั่วโมง ให้แคชคำตอบฝั่งเว็บ |
| ราคาเป็น `null` | ร้านยังไม่กำหนดราคาขายของรุ่นนั้น แสดงว่า "สอบถามราคา" |
| `availability` เป็น `order` ทุกรุ่น | ยังไม่มีรถในสต๊อก หรือยังไม่ได้ import ข้อมูลรถ |
