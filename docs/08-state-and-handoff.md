## 4. งานที่ค้างและตอบไปแล้วครึ่งทาง — ร้านย่อยคือ *สาขา*

เจ้าของยืนยันว่า **ร้านย่อยออกใบกำกับภาษีเองได้**

ข้อนี้เปลี่ยนคำตอบทั้งหมด: ถ้าออกใบกำกับภาษีเองได้ ในทางกฎหมายมันคือ *สาขา* ไม่ใช่ *ที่เก็บของ*
คำตอบทางเทคนิคจึงเป็น **"เพิ่มแถวใน `BRANCHES`"** ไม่ใช่ "สร้างชนิดข้อมูลใหม่"
ซึ่งแปลว่าสต๊อก การโอนย้าย รายงาน และ `inScope` ทั้ง ~60 จุด **ได้มาฟรีทันที**

สิ่งที่ยังไม่มีและต้องทำ:

1. **หน้าจอแก้สาขา** — ตอนนี้ `BRANCHES` (`index.html:1669`) เป็น `const` ที่ไม่มีหน้าจอแก้เลย
   ต้องทำแบบเดียวกับแท็บ `cf4` (จุดลงเวลา) ที่เพิ่งทำไป
2. **เลขสาขาสรรพากรและตัวนับเลขเอกสารของตัวเอง** — `branch_no` · `tax_id` · `doc_prefix`
   ฝั่ง SQL มีคอลัมน์พวกนี้อยู่แล้วในตาราง `branch` และมี `next_doc_no()` รองรับ
3. **ตัดสินเรื่องจุดลงเวลา** — ร้านย่อยที่กลายเป็นสาขาจะมี `branch_site` ของตัวเอง
   ตรงนี้รองรับอยู่แล้ว ไม่ต้องแก้อะไร

**ยังตอบไม่ได้ ต้องถามเจ้าของก่อนเริ่ม:** มีร้านย่อยกี่ร้าน · ชื่ออะไร · มีเลขสาขาสรรพากรแล้วหรือยัง
**อย่าเริ่มจนกว่าจะได้คำตอบ** เพราะจำนวนสาขามีผลกับหน้าจอและกับตัวนับเลขเอกสาร

## 5. เรื่องที่ตัดสินไปแล้ว อย่ารื้อโดยไม่มีเหตุผลใหม่

| เรื่อง | ตัดสินว่า | เพราะ |
|---|---|---|
| ยืนยันตำแหน่งด้วยไอพี WiFi ร้าน | **ไม่ทำ** | พนักงานบางคนใช้เน็ตมือถือ แยกไม่ออกระหว่าง "ไม่ได้ต่อ WiFi" กับ "ไม่ได้อยู่ที่ร้าน" |
| ธง "ลงเวลาพร้อมกันในระยะ 15 ม./90 วิ" | **ไม่ทำ** | ร้านเล็ก ยืนใกล้กันปกติ เพื่อนเตือนกันแล้วลงพร้อมกันคือพฤติกรรมที่ถูก · ธงที่ขึ้นกับคนทำถูกทำให้ผู้จัดการเลิกอ่านคิว แล้วธงอื่นตายตามไปด้วย |
| โหมดตรวจตำแหน่ง | **เริ่มที่ `watch`** | คิดและเก็บทุกอย่างแต่ยังไม่บังคับ · เก็บตัวเลขจริง 2-3 สัปดาห์แล้วค่อยตั้งรัศมีจากหลักฐาน แล้วสลับเป็น `enforce` |
| สต๊อกบนเว็บขายรถ | **บอกแค่ มี/เหลือน้อย/หมด** | ตัวเลขรายวันคือยอดขายรายรุ่นที่คู่แข่งดึงไปอ่านได้ |
| ลูกค้าเช็กสถานะ | **ลิงก์/รหัสเฉพาะตัว** ห้ามค้นด้วยเบอร์+ชื่อ | การค้นด้วยเบอร์คือเครื่องมือไล่เดาข้อมูลลูกค้าทั้งฐาน |
| QR บนใบเสร็จ | **ยังไม่ทำ** | ไม่มี `BarcodeDetector` ในเบราว์เซอร์ที่ใช้ทดสอบ และห้ามใช้ไลบรารีนอก จึงพิสูจน์ไม่ได้ว่าสแกนติด — ลิงก์+รหัสตัวหนังสือพอแล้ว |

## 6. กฎที่ได้จากการทำจริง — อยู่ใน `docs/04-design-system.md`

| § | สรุปหนึ่งบรรทัด |
|---|---|
| 9b | **ด่านอยู่ในฟังก์ชันที่เขียนข้อมูล ไม่ใช่ที่ปุ่ม** — ซ่อนปุ่มไม่ใช่การกัน |
| 9h | รวมหน้าที่สิทธิ์ไม่เท่ากัน แท็บต้องเป็นด่านจริง |
| 9i | **พิกัดเป็นหลักฐาน ไม่ใช่ตัวตัดสิน · เวลามาจากเซิร์ฟเวอร์** · ผลการตัดสินต้องถูกแช่ไว้ ไม่คิดใหม่ตอนวาดจอ · ยังไม่ตั้งจุด = ปล่อยผ่าน |
| 9j | **apply migration ผ่าน ไม่ได้แปลว่าใช้ได้** — ต้องยิงจริงทุก endpoint ด้วยสิทธิ์ของคนที่จะใช้จริง |
| 10 | คู่มือสร้างจากโค้ด ไม่ใช่จากความจำ |

สองบั๊กที่เจอตอนรัน migration จริง และจะพลาดซ้ำได้ง่ายมาก:

- **`app_setting.value` เป็น `jsonb`** — `('geo_mode','watch')` พังด้วย `22P02` เพราะ `watch` เปล่า ๆ ไม่ใช่ JSON
  ต้องเป็น `to_jsonb('watch'::text)` · ตัวเลขอย่าง `'120'` ผ่านเพราะเป็น JSON number
- **ฟังก์ชันที่เขียนข้อมูลต้องเป็น `volatile`** — `pub.order_status` เคยเป็น `stable` ทั้งที่ `insert` ลงตารางนับการเรียก
  `create function` สำเร็จ · advisor เงียบ · **แต่พังทุกครั้งที่เรียกจริง** เห็นเฉพาะตอนยิงผ่าน PostgREST

## 7. กับดักของสภาพแวดล้อมที่เสียเวลาไปแล้ว

- **`pkill -f` / `pgrep -f` ที่แพตเทิร์นตรงกับคำสั่งตัวเอง จะฆ่าเชลล์ตัวเอง** (exit 143/144) ใช้ `fuser -k 8123/tcp` แทน
  · กับดักเดียวกันคนละหน้า: `until ! pgrep -f "qa/run.js"; do sleep 10; done` **ไม่มีวันจบ**
  เพราะบรรทัดคำสั่งของตัวรอเองมีคำว่า `qa/run.js` อยู่ — ให้รอด้วย PID (`kill -0 <pid>`) แทน
- **เซิร์ฟเวอร์ทดสอบต้องเปิดจาก repo root** ไม่งั้น `index.html` หา asset ไม่เจอ (`tools/qa/run.js` จัดการให้แล้ว)
- **`tools/manual/build.js` เปิดเซิร์ฟเวอร์ 8123 ของตัวเอง** ต้องปิดของเราก่อน แล้วเปิดใหม่ทีหลัง
- **Node พาร์สสตริง ISO เป็น UTC** ส่วนหน้าเว็บตั้ง `Asia/Bangkok` — เทียบเวลาต้องคำนวณ**ในหน้าเว็บ** ไม่ใช่ใน Node
- **เบราว์เซอร์ในกล่องทดสอบออกเน็ตไม่ได้** (`ERR_CONNECTION_RESET` ทั้งผ่านและไม่ผ่านพร็อกซี)
  จะทดสอบ API จริงต้องใช้ `curl` · จะทดสอบหน้าเว็บต้องดักคำขอด้วย `page.route` แล้วป้อน payload ที่เก็บไว้
- **พร็อกซีของกล่องทดสอบสลับไอพีขาออก ~10 ตัว** ทดสอบ rate limit ผ่าน HTTP จึงไม่มีวันติด ต้องพิสูจน์ใน SQL
- `pgcrypto` อยู่ในสคีมา `extensions` บน Supabase → ต้องเขียน `extensions.gen_random_bytes`
- วิวใน Postgres รันด้วยสิทธิ์เจ้าของ (`security_invoker` ปิดโดยปริยาย) → **รายชื่อคอลัมน์ของวิวคือเส้นแบ่งความปลอดภัยทั้งหมด**
- `pgrst.db_schemas` ตั้งไว้ที่ role `authenticator` (ท้าย migration 15) **ค่านี้ชนะหน้า Settings → API → Exposed schemas**
